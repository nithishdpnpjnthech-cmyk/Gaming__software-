# Device Registration Implementation

## Architectural Flow
```
[Client Agent]                      [Backend API: DevicesController]
      │                                             │
      ├───── POST /api/devices/register ───────────>│
      │      (localDeviceId, deviceCode, hostname)  │
      │                                             ├── 1. Check localDeviceId exists
      │                                             │      If found -> return 200 OK
      │                                             ├── 2. Auto-generate DeviceCode if absent
      │                                             ├── 3. INSERT INTO devices (PENDING)
      │                                             ├── 4. INSERT INTO device_status (is_online=false)
      │                                             └── 5. Commit transaction
      │<──── 201 Created (id: BackendDeviceId) ─────┤
```

## Idempotency & Fault Tolerance
1. **Network Interruption Handling**: If the network drops while the backend responds with 201 Created, the client will retry with the exact same `localDeviceId`. The backend detects this and returns HTTP 200 OK with the existing record, avoiding duplicate device rows.
2. **Auto-Generated Identifiers**: Primary key `id` is exclusively generated by the backend (`gen_random_uuid()`). The client never controls primary keys.
